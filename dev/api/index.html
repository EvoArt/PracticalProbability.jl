PracticalProbability.BayesNet — Type
BayesNet(specs::Pair...; domains = Dict())

A discrete Bayesian network. Each spec gives one variable's conditional probability table (CPT):

@rv X Y Z
bn = BayesNet(
    X => [0.3, 0.7],                    # P(X)
    (Y | X) => [0.9 0.2; 0.1 0.8],      # P(Y | X): rows are Y, columns are X
    (Z | (X, Y)) => cat([0.5 0.4; 0.5 0.6], [0.1 0.7; 0.9 0.3]; dims = 3),
)

The first array dimension is the variable, the rest are its parents in the order written; every column must sum to one. Values are 1:n unless given in domains, e.g. domains = Dict(X => [:no, :yes]). The graph is read off the specs.

A named event (@event A) is a yes/no variable with values [true, false], and its table may give just the probability that it happens: A => 0.3 is P(A) = 0.3, and (B | A) => [0.9, 0.2] is P(B | A) = 0.9, P(B | Aᶜ) = 0.2.

Tables of integers or Rationals are kept exact (X => [1//3, 2//3]), and then compute returns exact rationals.

PracticalProbability.H — Method
H(X)
H(X, Y | Z; name = :P)
ℍ(…)

The (joint, conditional) entropy, in nats. Conditioning on a variable averages over it (H(X | Z) = ∑_z P(z) H(X | Z = z)); conditioning on an event such as Z(1) fixes it. name picks the distribution (H(X; name = :q) is H_q(X)).

Rules (in simplify): H(X | X, Z) = 0, conditioning that is independent of X (by a graph or assumed facts) drops out, the entropy of independent parts splits, and sums of entropies recombine by the chain rule (H(X | Z) - H(X | Y, Z) = I(X; Y | Z)). Explicit: chainrule, definition (E[-log P(X | Z)]), entropies.

H(f::Family) is the closed-form entropy of a distribution family.

PracticalProbability.bayes — Method

PracticalProbability.bounds — Method
bounds(query; dag = nothing, monotone = false) -> CFBounds or PExpr

Tian–Pearl bounds on a probability of causation for a binary treatment X (values x, x′) and outcome Y (values y, y′), from experimental terms P(y | do(x)) and observational terms P(x, y):

  • PNS, P(Y(Do(Event(X, x)))(y), Y(Do(Event(X, x′)))(y′)): the outcome happens with the treatment and not without it;
  • PN, P(Y(Do(Event(X, x′)))(y′) | X(x), Y(y)): for a treated unit with the outcome, the outcome would not have happened untreated (probability of necessity);
  • PS, P(Y(Do(Event(X, x)))(y) | X(x′), Y(y′)): for an untreated unit without the outcome, the treatment would have produced it (probability of sufficiency). (PN and PS have the same form: observed (x, y) and the opposite counterfactual; here the first value of each is taken to be the one written in the counterfactual's Do.)

With monotone = true (Y is monotone in X: no unit with y_{x′} and y′_x) the bounds meet and the point value is returned. With dag (a DAG or ADMG) the experimental terms are replaced by their identified observational expressions. compute gives the numeric interval.

PracticalProbability.deduce — Method
deduce(query, facts...) -> Solution

The value of a probability expression implied by known values and facts about named events. Facts are as for assume:

@event A B
deduce(P(A ∩ B), P(A) => 0.3, P(B) => 0.5, P(A ∪ B) => 0.6)   # 0.2
deduce(P(A ∪ B), P(A) => 0.3, P(B) => 0.4, A ⟂ B)             # 0.58
deduce(P(A | B), P(B | A) => 0.9, P(A) => 0.01, P(B | A') => 0.05)

The known values are linear constraints on the probabilities of the 2ⁿ cells of the events; disjoint and implies add more, and independence adds product equations as soon as enough is known. If the facts do not pin the query down, the result says so (s.determined == false), names the unknown terms, and gives the tightest bounds the linear facts allow (by linear programming over the cell probabilities): deduce(P(A ∩ B), P(A) => 0.3, P(B) => 0.5) is between 0 and 0.3 (the Fréchet bounds). Independence facts are used only where they have become linear, so with them the bounds can be wider than the tightest possible. Inconsistent facts are an error.

With exact values (P(A) => 3//10, or integers) the system is solved in rational arithmetic and the answer is an exact Rational: deduce(P(A | B), P(B | A) => 9//10, P(A) => 1//100, P(B | A') => 1//20) is 2//13.

A variable's incoming coefficients are solved once there is a set Y of variables, none of them the variable or its siblings, each already solved or not half-trek reachable from it, with a system of half-treks from Y to its parents without sided intersection. The coefficients come out as rational functions of the covariances σ[a,b] (covariance_symbol), by Cramer's rule on [(I - Λ)ᵀ Σ]_{Y, pa(v)} λ = [(I - Λ)ᵀ Σ]_{Y, v}.

Success means every coefficient is identified for almost every parameter value. Failure is conclusive when the criterion's "HTN" condition holds, which this does not check: an unsolved variable may still be identifiable by other means.

PracticalProbability.importance_weight — Method
importance_weight(target, proposal; dag = nothing, data, sampled, normalized = false)
    -> ImportanceWeight

The importance weight w = target / proposal, derived symbolically.

target and proposal are probability expressions. The proposal is usually written with a named distribution (@density q, then q(θ | y)), and may reuse terms of the target's distribution: a proposal P(θ) is the target's own prior, P(X₂ | X₁) its own transition kernel. Terms of different distributions never cancel; identical terms do.

Steps, each recorded with its justification:

  1. With no graph for the target, a conditional target P(θ | y) is written P(θ, y) / P(y).
  2. With dag (a DAG for the distribution :P, or a Dict from names to DAGs), every term is written in its distribution's factorisation (see expand); terms that already are factors stay as they are.
  3. Everything is collected into one fraction, and common factors cancel (see simplify).
  4. Unless normalized = true, factors that depend only on data (by default the conditioning variables of a Prob target) are dropped: the weight is then known up to a constant, as in self-normalised importance sampling.

sampled (by default, the free targets of the proposal's terms that are not data) only labels the result; everything the weight depends on other than data counts as a particle variable, so in sequential Monte Carlo pass the observation as data and the previous state stays in the weight.

@rv θ Y
@density q
g = @dag θ → Y
importance_weight(P(θ | Y), P(θ); dag = g)       # w ∝ P(Y | θ)
importance_weight(P(θ | Y), q(θ); dag = g)       # w ∝ P(θ) P(Y | θ) / q(θ)

Also accepts two generative models (anything generative does): see the method for models below.

The combination found is the proof.

When there is no proof, prove searches small distributions for a counterexample. Without one the inequality may still be true but not Shannon-type (e.g. the Zhang–Yeung inequality). Two ways beyond Shannon:

  • nonshannon = true adds every instance of the Zhang–Yeung inequality 2I(C; D) ≤ I(A; B) + I(A; C, D) + 3I(C; D | A) + I(C; D | B) (over four of the variables) as a further generator;
  • copies = [(R, O), …] applies the copy lemma (Zhang–Yeung, Dougherty– Freiling–Zeger): new variables R* with the same joint distribution with O as R, and independent of everything else given O. Inequalities about the original variables proved with them hold for every distribution. copies = :auto tries single copies of one or two variables over one or two others until one gives a proof.
prove(H(X, Y) <= H(X) + H(Y))                          # I(X; Y) ≥ 0
prove(MI(X, Z) <= MI(X, Y); assume = [X ⟂ Z | Y])      # data processing
prove(MI(X, Y | Z) <= MI(X, Y))                        # false: Z = X ⊻ Y

PracticalProbability.recover — Method
recover(P(Y | X), g::DAG, S; external = [], measured = nothing, latent = [], maxsize = 3) -> PExpr
recover(P(Y | Do(X)), g::DAG, S; …)

Recover a query about the whole population from data selected on the event S (a node of g with no children, declared with @event S; its parents are what selection depends on). Terms conditioned on S come from the biased data, which covers the variables in measured (default: all observed ones); terms without S come from external unbiased data on the variables listed. latent lists hidden variables of g.

Conditional distributions P(Y | X) (Bareinboim, Tian & Pearl 2014):

  • without external data, P(Y | X) is recoverable if and only if Y ⟂ S | X, as P(Y | X, S) (Theorem 1), so a failure here is final;
  • with external data on X and some C: ∑_c P(Y | X, c, S) P(c | X) when (C, X) separates S from Y, decided by one d-separation test over the largest admissible C (Theorems 2–3), then shrunk to a minimal set;
  • with external data on Y but not all of X: through P(X | Y) and Bayes' rule (Corollaries 3–4); or through the joint P(X, Y) (Corollary 5).

Causal effects P(Y | Do(X)):

  • in a model without hidden variables, recoverable without external data if and only if no variable in D = An(Y) of G[V ∖ X] is an ancestor of S, as ∑_{D∖Y} ∏_{v∈D} P(v | pa(v), S) (Bareinboim & Tian 2015, Theorem 2);
  • the selection-backdoor criterion (BTP 2014, Theorem 5): ∑_z P(Y | X, z, S) P(z);
  • with hidden variables, the RC algorithm (Bareinboim & Tian 2015, Fig. 4), which recovers the c-components that contain no ancestor of S, peels them off and identifies the query from them;
  • finally the query is identified by ID and each term recovered on its own, using external data where needed (front-door-like cases).

Throws NotRecoverable when nothing applies; the reason says when the criterion that failed is complete (no method can recover the query).

PracticalProbability.simplify — Method
simplify(expr; dag = nothing, assume = nothing, combine = true, trace = false, maxsteps = 200)
simplify(expr, dag; kwargs...)
simplify(expr, facts::Facts; kwargs...)

Rewrite expr to a simpler equal expression. Rules applied until none applies:

  • the event identities (A ∩ Aᶜ = ∅, (Aᶜ)ᶜ = A, A ∪ Ω = Ω, P(∅) = 0, P(Ω) = 1, …), one at a time, for terms built with @hold (∪, ∩, ' and P otherwise apply them when the term is built);
  • P(A, B | A) = P(B | A), P(A | A) = 1, P(Aᶜ | A) = 0, P(A ∪ B | A) = 1;
  • marginalisation, ∑_B P(A, B | C) = P(A | C) and ∑_B P(B | C) = 1, with factors free of the summed variables moved outside the sum;
  • the chain rule backwards, P(A | B, C) P(B | C) = P(A, B | C) (combine = false turns this off);
  • quotients: cancelling common factors and P(A, B | C) / P(B | C) = P(A | B, C);
  • sums: P(E | C) + P(Eᶜ | C) = 1, P(A ∩ E) + P(A ∩ Eᶜ) = P(A) (also with common factors), 1 - P(E) = P(Eᶜ);
  • with a graph: conditional independence by d-separation, and do-calculus rules 1–3 for terms with Do(⋅), and variable elimination that uses the graph to widen a factor's conditioning before the chain rule (∑_B P(B | A) P(C | B) = P(C | A) under A → B → C);
  • with assume (assume facts): assumed independence drops conditioning and splits joints (P(A ∩ B) = P(A) P(B)), disjoint events have P(A ∩ B) = 0 and P(A ∪ B) = P(A) + P(B), and implies(A, B) gives P(A ∩ B) = P(A);
  • expectations: linearity, constants, E[𝟙(A)] = P(A), taking out what is known, the tower property, and variances/covariances of constants and independent variables (see E).

A graph describes one distribution. dag = g (or simplify(expr, g)) applies g to the default distribution P only; for named distributions pass a Dict, e.g. dag = Dict(:P => g, :q => gq). Terms of a distribution with no graph get no independence rules, and terms of different distributions are never combined.

With trace = true returns a Derivation recording each step and its justification.

By default the first rule that applies is taken at each step. With search = true the order of the rules is searched instead (a beam search of width beam over every rule at every position), and the smallest expression no rule rewrites further is returned; the first-match result is kept when nothing smaller is found.

laws (laws) gives the distributions of variables, so that moments of standard distributions are filled in (E[X] = μ for X ~ Normal(μ, σ)).

PracticalProbability.smc_weight — Method
smc_weight(target, proposal) -> SMCWeight

The incremental importance weight of sequential Monte Carlo, derived symbolically. target is the unnormalised path target as a product over a plate, γ_t = ∏_{s=lo}^{t} f(s), typically the joint density of states and observations up to time t; proposal is the kernel that extends a particle by x[t].

The factors of f(t) are then read as the graph of one time slice, and terms of the target's distribution in the proposal are written in that graph's factorisation, so the locally optimal proposal P(x[t] | x[t-1], y[t]) reduces too.

@index t 1:T
@index s 1:t

smc_weight(γ, P(x[t] | x[t-1]))            # bootstrap:       P(y[t] | x[t])
smc_weight(γ, P(x[t] | x[t-1], y[t]))      # locally optimal: P(y[t] | x[t-1])
smc_weight(γ, q(x[t] | x[t-1], y[t]))      # anything else

Evaluate expr with the event identities switched off: ', ∪, ∩ and P(⋯) build exactly what is written instead of simplifying on the way, so @hold P(A ∩ A') is the term P(A ∩ Aᶜ) rather than 0. simplify then applies the identities one at a time, and with trace = true records each one (A ∩ Aᶜ = ∅, then P(∅) = 0):

e = @hold P(A ∩ A')
Equation(e, simplify(e))          # P(A ∩ Aᶜ) = 0
simplify(e; trace = true)

Only construction is held: other operations (+, *, …) behave as usual, and simplify works with the identities on even when called inside @hold.

PracticalProbability.@sampleevents — Macro
@sampleevents draws begin
    A = σ > 0.2
    B = μ > 0
end

Define named events by conditions on draws. Each line binds a new named event (A, B) in the calling scope and evaluates its condition draw by draw. Names in a condition are columns of draws (a Tables.jl table such as a DataFrame or an MCMCChains chain, a NamedTuple or a Dict of vectors), or ordinary variables if no column has that name. Conditions are broadcast (abs(μ) < 1, 0 < μ < 1, (μ > 0) & (σ < 1); &&/|| work too), and θ[1] reads the column named θ[1]. Returns the SampleEvents.

    A = σ > 0.2
    B = μ > 0
end
